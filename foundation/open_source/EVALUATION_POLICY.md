# Lidiya Open Source Evaluation Policy

## 目的

讓所有新視窗能判斷開源項目是否真正有助於家，而不是只看熱門度、星數或宣傳。

## 五項評分

每項 0–20 分，總分 100。

1. **需求適配**：能否降低目前任務的 Token、時間、人工介入或失敗率。
2. **來源可信**：是否官方上游、維護者可辨識、授權明確、Release 與 commit 可固定。
3. **維護健康**：近期是否持續更新、Issue／安全公告是否處理、是否已封存。
4. **可控與可回退**：能否離線或 localhost 使用、權限是否可縮小、能否完整移除與回復。
5. **資源效率**：是否適合目前 RTX 4050 6GB、16GB RAM 與未來硬體感知排程。

## 判定門檻

- **0–39：忽略**：不符合需求、來源不明或風險過高。
- **40–59：觀察**：保留雷達，不下載、不測試。
- **60–74：沙盒評測**：固定版本後，在隔離候選區測試。
- **75–89：候選導入**：建立封包、Manifest、SHA256、回退與影子模式。
- **90–100：高信任候選**：仍須使用者核准；不代表可以直接進正式核心。

## 強制阻擋條件

任何一項成立即不得自動導入：

- 授權不明、來源冒名或 Repository 已遭封存且無可信接手者。
- 要求停用監控、取得管理員權限、公開入站連線或任意 Shell。
- 會把 Key、Token、密碼或私人資料寫入 Repository、日誌或聊天。
- 無法固定版本／commit、無法計算成品 SHA256、無法回退。
- 功能與家中現有工具重複，但沒有可量化的成本或成功率提升。

## 成長規則

- 雷達可以自動更新資料，不得自動安裝。
- 高分候選先進沙盒，再進影子模式。
- 只有實際使用頻率、成功率、成本與人工介入率證明有價值，才建議升級。
- 每項技能需保留「最後已知良好版本」與可還原封包。
- 正式合併、Release、模型下載、公開發布與實體控制仍需博玄逐次解鎖。
